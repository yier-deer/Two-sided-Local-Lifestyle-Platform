# ScoutBite 三分钟演示稿

更新：2026-10-11。目标：面试 / 项目答辩。真实服务已完成联调，也保留独立模式作现场备选。

## 准备

执行 `powershell -ExecutionPolicy Bypass -File deploy\start-demo.ps1`，打开 `http://127.0.0.1:5173/#/discover`。

展示真实工程链路时，执行 `deploy\start-all.ps1` 和 `python deploy\prepare-demo.py`；顶部切「真实服务」并登录。当前已验证 Native 基础设施，自动启动不依赖本机 Docker。真实门店为「潮牛火锅·西湖1号店」，演示套餐「演示·双人火锅套餐」198元，券「演示·满100减20」，准备文件见 `deploy/logs/demo-scenario.json`。

首次进入已是演示用户“辣妹小队长”。重复演示可从侧栏「演示导览」恢复初始数据。模式始终显示在顶部；点击可切真实服务，切换后需重新登录。

现场开口：「这是探店雷达 ScoutBite，一套用户和商家的本地生活平台。用户能从推荐走到消费评价，商家能从反馈走到经营行动。Agent 的推荐有引用，发布需要人确认，交易还有状态与权限校验。当前是明确标识的本地演示，模型与并发证据另外展示。」

## 第一段：有依据地选择 · 约 50 秒

1. 在「发现好去处」查看店铺照片、距离、类别；切「咖啡茶饮」再回全部，展示搜索与排序。
2. 打开「AI 探店助手」，点击「朋友聚餐，热辣一点」。
3. 指出推荐理由与「留意一点」，点击任一「评价」按钮展示原文。
4. 点击某家店的「看看套餐」，进入店铺详情。

讲解：「推荐来自已审核候选，每家都说明限制。引用可以回到原评价核对。真实模式通过 Java 门面调用 Python Agent，工具只读取瘦事实；负订单的历史种子评论会标为展示样本，新消费评价绑定真正核销记录。每次问题独立处理，预算按可售套餐起价参考，需要核对人数与实际消费。」

## 第二段：一次消费，真人签字 · 约 70 秒

推荐使用示例店「蜀味里 · 巷子火锅」（`/#/shop/1`）。

真实模式使用同一地址下的「潮牛火锅·西湖1号店」，选名称明确带「演示」的套餐/券。用户在同一个门店先消费，再到商家回复；管理页面默认选择有评价的门店，并保持跨页面选择。

1. 领满减券，购买「招牌双人火锅套餐」。
2. 结算中选择优惠券：原价 198 元，满 100 减 20，实付 178 元。
3. 提交订单 → 「模拟支付」→ 切「待核销」→ 「到店核销」→ 确认。
4. 切「待评价」→ 点击最新订单的「写评价 · AI 帮我起草」。
5. 填写真实体验笔记，设评分，生成草稿，修改正文中的一句话。
6. 指出发布按钮仍不可点，勾选真实性确认后再发布。
7. 点击「查看我的评价」，核对修改后的文字确实展示。

讲解：「领券和用券是两步，结算使用的是我的持券记录 ID。支付只代表购买套餐，核销才代表消费。评价只允许已核销且未评价的订单。生成不发布，编辑后的内容和评分由用户确认提交。取消或未核销退款会恢复库存和券。」

时间紧时，初始订单 #101 已核销，可直接进入评价助手。只有 #101 是演示快捷数据，不要说它是刚才新下的订单。

## 第三段：商家听见并行动 · 约 50 秒

1. 侧栏「进入商家中心」直接切演示商家。
2. 查看经营概览：指标来自当前示例订单，刚才的消费会反映在其中。
3. 打开「评价管理」，找到刚发布的评价，输入具体回复并发布。
4. 回用户店页确认「商家」标识，再切回商家。
5. 打开「AI 经营助手」→ 分析，展示「观察 / 假设 / 建议」。

讲解：「商家看自己的订单，能核销到店消费，不能代用户支付或退款。回复是公开可见的，身份标记由服务端决定。Agent 分开说数据、可能的原因和下一步建议，不把相关性当因果，也不会替商家自动改价或发券。」

## 可选：审核与供给 · 加 30–60 秒

- 登录页「店铺审核」进入管理员队列，批准「青禾 · 社区咖啡」，切用户后搜索青禾。待审店的直接套餐查询与下单同样被拦截。
- 商家「套餐与优惠券」创建、编辑或下架套餐；用户刷新店页验证可售供给变化。
- 「探店笔记」切新店探索，展开底部排序记录查看权重；示例排序只用于机制说明。

## 真实工程补充

执行 `deploy\start-all.ps1`，本机 Auto 选择项目隔离 Native PG/Redis；Docker可选。顶部切「真实服务」，使用 README 中种子账号登录。真实商家只拥有指定的无主种子店，店名和数值以实际返回为准，不要求与示例店相同。

真实调用记录位于「演示导览」底部，可读取当前用户 trace；展示工具、输入、输出和时延。历史评测与券压测报告保留在 README / evals，必须注明是历史运行结果，不能用浏览器示例证明并发或模型效果。

最新证据：真实API13/13、并发/超时6/6、真实浏览器2/2；Agent全量65/65，生成草稿新增评价0。最新报告 `evals/reports/full-20261011-release.md`。前端15项、独立浏览器12条、Java74项、Agent Python42项通过。商家评测15例映射1家真实门店，数字是本地验证，不代表生产吞吐或所有输入零幻觉。

## 故障时继续

- 实时模型失败：展示明确错误，回店铺与订单继续业务操作；评价助手可「自己写」。
- 种子订单已评价：重新消费核销后再评；独立演示也可从导览重置。
- 实时账号切错：登录页直接切角色；真实模式不会自动切换示例身份。
- 定位拒绝：保留湖滨商圈列表，仍可以搜索浏览。
- 5173 被其他项目占用：`deploy\start-demo.ps1 -Port 5174`，打开脚本打印的地址。
