# 已知问题（诚实清单）

> 写在 README 的对面：这个项目测到了什么、没测到什么、哪里是演示级妥协。
> 每条含：现象 / 根因 / 影响 / 升级路径 / 为什么 MVP 不做。
> 面试被问到任何一个，能按这个结构答 = 加分项而不是减分项。

## 1. 菜品级编造抓拍 2/4 未全过（评测负例）

- **现象**：评测 no_fabrication 指标 2/4——rev-009 草稿写"龙虾刺身新鲜"、rev-010 写"和牛和牛舌品质不错"，而订单事实里没有这两道菜（[evals/reports/latest.md](../evals/reports/latest.md) 第 5 节）。
- **根因**：提示词约束是软约束（"只依据事实清单"），LLM 在菜品维度有概率性发挥；程序化检测只能抓"诱饵词出现且无免责上下文"，抓不住语义级编造。
- **影响**：草稿发出去会让商家回复不存在的问题。
- **升级路径**：菜品白名单进 prompt 硬枚举；judge 抽查加菜品维度；最彻底的是结构化输出（JSON schema 限定菜名字段取值）。
- **MVP 为什么不做**：结构化输出会牺牲草稿的自然语言质感；先用评测把问题暴露出来，比直接掩盖更诚实。

## 2. 评论聚类 = 关键词分桶，不是语义聚类

- **现象**：商家端"高频意见"按关键词正则分桶（如"排队/等位"桶）。
- **根因**：MVP 没引入 embedding。
- **影响**："上菜慢"和"出餐慢"会进不同桶；同义表述被拆散，聚类数虚高。
- **升级路径**：sentence-transformers 做句向量 + HDBSCAN；或直接让 LLM 归类（但成本上升且引入新的不稳定）。
- **MVP 为什么不做**：40 家店 × 20 条评价的量级下，关键词桶的召回已够演示；语义聚类是精度优化，不是 MVP 门槛。

## 3. 评价草稿仓是内存 dict（重启即丢）

- **现象**：agent-api 的 drafts.py 用进程内字典存草稿，服务重启草稿全没了。
- **根因**：时为快速打通"生成→预览→发布"链路选了内存实现。
- **影响**：演示中途重启 = 用户草稿丢失；多实例部署时草稿不共享。
- **升级路径**：草稿落 PG 表（user_id + draft 内容 + 状态），或 Redis 带 TTL。
- **MVP 为什么不做**：单实例演示场景下不丢；加表要动 schema，收益只有重启容错。

## 4. 多轮对话无跨轮状态

- **现象**：sessionId 透传了，但每轮推荐都从零开始——上一轮"不吃辣"这轮不记得。
- **根因**：graph.py 状态是单轮 scope。
- **影响**：连续追问体验差（"换一家"做不到）。
- **升级路径**：LangGraph checkpointer（SQLite/PG）挂 conversation 级 state。
- **MVP 为什么不做**：评测集全部是单轮用例；多轮先不做，评测就不含多轮指标——做了也测不了，等于白做。

## 5. Redis 券余量日常对账未自动化

- **现象**：做了**关单链路**对账（超时→库存/券归位），但 Redis 券余量 vs DB total-issued 的**日常巡检对账**没有定时任务。
- **根因**：余量镜像只在领券/关单两个写点维护，没有周期性校准。
- **影响**：极端情况（进程崩溃在两写点之间）余量漂移不会被发现。
- **升级路径**：定时任务对 `coupon:{id}:stock` vs `total - count(user_coupons)`，漂移超阈值告警 + 以 DB 为准回填。
- **MVP 为什么不做**：压测 200 并发三查全过说明正常路径一致；崩溃窗口对账是生产化要求。

## 6. 评测边界：p95 样本量小 + judge 同族偏差

- **现象**：p95 基于 30/20/15 个用例，统计意义弱；judge 用 DeepSeek 评 DeepSeek 的输出（同族偏好）。
- **根因**：full 模式 65 例跑一次 ≈¥0.6，加大样本和换 judge 模型都是成本问题。
- **影响**：p95 数字看趋势可以，当 SLA 不行；judge 分数可能系统性偏高。
- **升级路径**：用例翻 10 倍 + judge 换 GPT 系交叉评 + 第④层人工抽检对齐（人工 5 例已有）。
- **MVP 为什么不做**：报告里如实标注了偏差（第 3 节脚注）——记录局限本身就是评测的一部分。

## 7. CORS 全开 + demo 密码明文写在 README

- **现象**：WebConfig 允许 `*`；README 登录表里密码明文。
- **根因**：本地演示项目，无公网暴露面。
- **影响**：如果这个代码被直接部署到公网 = 事故。
- **升级路径**：CORS 收敛到前端域名；密码从环境变量注入 seeder；JWT 密钥同理。
- **MVP 为什么不做**：演示机的威胁模型里没有攻击者；但必须在本文档声明，防止代码被拿去直接上生产。

## 8. 图片上传未实现（imageKeys 字段空挂）

- **现象**：评价/帖子表有 imageKeys 字段，接口也收，但 MinIO 上传链路没做——存进去的永远是空数组。
- **根因**：Day 排期里图片处理被砍，字段先占位。
- **影响**：前端评价晒图功能是死的。
- **升级路径**：MinIO 预签名 URL 直传（前端拿 URL → 直传 OSS → 回填 key），服务端不经手图片流。
- **MVP 为什么不做**：预签名直传是一整条独立链路（签名服务+前端上传组件+CORS 配置），与 Agent 主线无关。

## 总结：这份清单怎么用

- **演示时**：不主动讲，被问到任何一条按"现象→根因→升级路径"答。
- **简历上**：known-issues 的存在本身就是加分项——知道边界比假装完美更能证明工程判断。
- **复习**：对照 [文档-名词表](../学习指南/文档-名词表.html) 的"诚实记录"条目。
